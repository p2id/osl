# Security Policy

## Reporting

Do not publish undisclosed vulnerabilities as public issues.

Provide a minimal description of:

- affected project;
- affected version or commit;
- reproduction steps;
- impact;
- suggested mitigation, if known.

## Project Security Baseline

Projects should consider:

- dependency scanning;
- secret detection;
- input validation;
- least-privilege permissions;
- secure defaults;
- dependency pinning where appropriate;
- reproducible builds;
- backup and recovery testing;
- audit logging for sensitive operations.

Security-sensitive projects should document threat models and known limitations.

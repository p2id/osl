# Contributing

Contributions are welcome across documentation, research, software design, implementation, testing, tooling, and project operations.

## Before Opening a Pull Request

- Explain the problem being solved.
- Keep the change focused.
- Update affected documentation.
- Add tests when behavior changes.
- Avoid unrelated formatting churn.
- Do not include secrets, private data, or unverifiable claims.

## New Projects

New project proposals should include:

- problem statement;
- intended users;
- MVP scope;
- non-goals;
- architecture sketch;
- acceptance criteria;
- maintenance expectations;
- license choice.

## Quality

Contributions should favor clarity, reproducibility, portability, security, and maintainability over unnecessary complexity.

## AI-Assisted Contributions

AI-assisted work is allowed when the contributor is responsible for reviewing it. Generated code must pass the same tests, security checks, licensing review, and maintainability standards as manually written code.
